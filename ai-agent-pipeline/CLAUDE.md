# 프로젝트 컨텍스트 (Claude Code 자동 로드)

이 파일은 Claude Code가 이 프로젝트에서 작업을 시작할 때 자동으로 읽는 컨텍스트입니다.
전체 설계 배경과 지금까지의 대화로 만들어진 요구사항은 아래 문서에 있으니, 먼저 읽고 작업하세요.

## 필수로 먼저 읽을 문서 (순서대로)
1. `docs/requirements.html` — 전체 설계 배경 (탭 9개: 파이프라인/라우팅로직/교차고려사항/에이전트선택UI/
   CTO아키텍처/결정사항&확인필요/이슈히스토리/지식베이스축적/**구현 반영사항**)
   → **09번 "구현 반영사항" 탭이 가장 중요** — 실제 코드로 옮기면서 고친 내역이 최신 상태로 정리되어 있음
2. `README.md` — 실행법, 사용법
3. `ARCHITECTURE.md` — 구조도, 기술스택 선택 근거, 각 설계 원칙이 코드 어디에 구현됐는지 매핑

## 프로젝트 한 줄 요약
기획→설계→개발→테스트→납품까지 여러 역할의 AI 에이전트가 순차적으로 작업하고, 사람은 CTO 에이전트
하나와만 대화하며 전체 진행을 파악하는 로컬 자동화 시스템. Next.js 대시보드(화면) + 독립 Node.js
엔진(실제 파이프라인 실행) + 파일 기반 state 공유, DB 없음.

## 지금 상태 (요약)
- 대시보드에서 파일 업로드 → 에이전트 선택(프리셋/커스텀) → 시작 버튼까지 한 흐름으로 동작함
- 커스텀 선택은 완전히 자유로움 (필수 단계도 뺄 수 있음, 막지 않고 경고만)
- 의존성 경고는 `pipeline.config.json`의 `dependsOn`을 기반으로 모든 단계에 대해 일반화되어 뜸
- CTO 대화는 로컬 `claude` CLI를 실제로 호출함 (미설치 시 규칙기반 폴백)
- 요구사항 파일(워드/엑셀/PPT/PDF 등)은 엔진이 미리 읽지 않고 경로만 넘겨 Claude Code가 직접 읽음
- 역할별 모델(haiku/sonnet/opus)을 pipeline.config.json에서 지정 가능
- 실제 모드 실행 전 `claude auth status`로 로그인 여부를 자동 체크함 (엔진 시작·대시보드 시작버튼·CTO 대화 3곳)
- 토큰 사용량은 `/usage`(헤드리스 미지원 확인됨) 대신 로컬 세션 로그(~/.claude/projects/*.jsonl)를 직접 파싱해서 표시 (파이프라인 시작 시 자동 1회 + 수동 "지금 체크")
- 신규 프로젝트 / 기존 프로젝트 수정 두 모드 지원 — 기존 모드는 output_path 존재 검증, 업로드 파일을 "변경 요청"으로 처리, 기존 구조 우선 파악 후 최소 변경
- 12단계 전부 PM 자동 재시도/티어 라우팅 적용됨 (예전엔 개발·리뷰·테스트만). 엔진/대시보드 코드 중복은 dashboard/lib/engineBridge.ts로 제거됨 (engine/lib를 직접 require)

## 다음에 손볼 만한 것 (README.md 5·7번 섹션 · `⚠️ TO VERIFY` 주석과 동일)
- `engine/lib/claudeClient.js` — ✅ 헤드리스 모드 권한 플래그(`--permission-mode acceptEdits`)와
  15분 타임아웃은 이미 추가함. 남은 건: 이 모드가 Bash 도구까지 커버하는지 실제 확인,
  `--print`/`--output-format`/`--model` 등 기본 옵션명 재확인.
- `engine/lib/knowledgeBase.js`의 `addPattern()` — 정의만 있고 실제로 호출하는 곳이 없어서
  지식 베이스 탭이 항상 비어있음. 연결 흐름을 만드는 게 다음 우선순위.
- `engine/lib/usageMonitor.js` — JSONL 세션 로그 필드 실제 구조 확인.
- `engine/agents/dev.js` — 실제 파일 편집(코드 작성)까지 연결.
- 프로젝트 간 격리(여러 프로젝트 동시 진행) 미구현 — `state/` 하나가 프로젝트 1개만 처리 가능.
- Windows에서 대시보드가 띄우는 백그라운드 엔진 프로세스의 생존 여부 미검증.
