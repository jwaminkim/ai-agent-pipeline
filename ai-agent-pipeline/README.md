# AI 에이전트 개발 파이프라인

기획 → 설계 → 개발 → 테스트 → 납품까지, 여러 역할(기획자/PM/PL/개발자/리뷰어/테스터 등)을 하는
AI 에이전트들이 순차적으로 작업하고, 사람은 **CTO 에이전트 하나와만 대화**하며 전체 진행 상황을
파악할 수 있도록 만든 로컬 자동화 시스템입니다.

전체 요구사항 정의 배경(대화 히스토리 기반 설계 문서)은 [`docs/requirements.html`](./docs/requirements.html)에
그대로 들어있습니다. 구조/설계 근거가 궁금하면 그 문서를 먼저 열어보세요.

---

## 1. 프로젝트 구성

```
ai-agent-pipeline/
├── dashboard/        Next.js 대시보드 (사람이 보는 화면)
├── engine/           오케스트레이터 엔진 (독립 Node.js 프로세스 — 실제 에이전트 호출/재개/체크포인트)
├── state/            대시보드 ↔ 엔진이 공유하는 파일 기반 상태 (JSON)
├── docs/
│   └── requirements.html   원본 요구사항 정의 문서 (탭 9개짜리 — 09번 "구현 반영사항"이 최신 변경이력)
└── README.md / ARCHITECTURE.md
```

**중요**: `dashboard`(화면)와 `engine`(실제 파이프라인 실행)은 **서로 다른 프로세스**입니다.
왜 이렇게 나눴는지는 [`ARCHITECTURE.md`](./ARCHITECTURE.md)에 설명해뒀습니다.

## 2. 실행 방법

### 2-1. 사전 준비
- Node.js 18 이상
- (실제 파이프라인을 돌리려면) [Claude Code](https://claude.com/product/claude-code) CLI가 로컬에 설치 및 로그인(Pro/Max 구독)되어 있어야 합니다.
  ```bash
  # 설치되어 있는지 확인
  claude --version
  ```

### 2-2. 설치
```bash
cd ai-agent-pipeline
npm run install:all
```

### 2-3. 실행 — 권장 방법 (버튼으로 시작)

```bash
npm run dashboard
```
브라우저에서 `http://localhost:3000` 접속 → **"① 프로젝트 시작" 탭**에서 파일 업로드 → 기술 스택
설정 → 에이전트 선택까지 마친 뒤 **"선택한 에이전트로 파이프라인 시작"** 버튼을 누르면, 대시보드가
엔진 프로세스를 직접 실행합니다 (터미널을 따로 열 필요 없음). 데모(드라이런) 모드 체크박스로
Claude Code 없이 흐름만 먼저 확인할 수 있습니다.

### 2-4. 대안 — 엔진을 터미널에서 직접 실행하고 싶을 때

```bash
# 터미널 1
npm run dashboard

# 터미널 2 (실제 모드는 Claude Code 로그인 필요)
npm run engine        # 실제 모드
npm run engine:demo   # 드라이런 모드
```
로그를 터미널에서 실시간으로 직접 보고 싶거나, 대시보드 없이 엔진만 테스트하고 싶을 때 사용하세요.
`npm run dev`(대시보드+엔진 데모를 `concurrently`로 동시 실행)도 여전히 쓸 수 있지만, 위 버튼 방식이
더 간단하고 이제는 기본 권장 방법입니다.

## 3. 사용 방법

모든 탭 상단에는 **최근 5시간 · 7일간 실제 토큰 사용량**(입력/출력, 메시지 건수)이 표시됩니다.
파이프라인을 시작하면 첫 단계 전에 자동으로 한 번 확인하고, "지금 체크" 버튼으로 언제든 수동 재확인할
수 있습니다. (Claude Code의 `/usage` 명령은 헤드리스 모드에서 작동하지 않아서, 대신 로컬 세션 로그를
직접 읽어 보여주는 방식입니다 — 플랜별 정확한 한도가 공개되어 있지 않아 "한도 대비 %"는 표시하지
않고 실제 토큰 수치를 그대로 보여줍니다.)
**% 표시를 보고 싶다면** 터미널에서 `claude setup-token`으로 토큰을 발급받아 `CLAUDE_CODE_OAUTH_TOKEN`
환경변수로 설정하세요 — 비공식 API를 통해 5시간/7일 한도 대비 %가 추가로 표시됩니다 (실패해도 원시
수치 표시에는 지장 없음).

1. **대시보드 접속 후 "① 프로젝트 시작" 탭에서:**
   - 요구사항 파일을 업로드합니다 (여러 개 가능, 워드/엑셀/PPT/PDF/텍스트 등 형식 자유 — 파일을
     미리 텍스트로 변환하지 않고 기획 에이전트가 Claude Code의 파일 읽기 능력으로 직접 열어서 분석합니다.
     단, 데모 모드에서는 실제로 파일을 읽지 않습니다).
   - **기술 스택을 설정합니다**: 언어 · 프레임워크 · 프로젝트 유형 · UI 프레임워크 · ORM · 프로젝트가
     만들어질 위치(output_path)를 직접 입력하거나, "AI에게 추천받기"로 업로드한 파일 기반 추천을 참고해
     입력할 수 있습니다. 여기서 지정한 내용은 설계 · 개발 에이전트가 반드시 따릅니다.
     **신규 프로젝트인지, 이미 존재하는 프로젝트를 수정하는 건지도 여기서 선택**하세요 —
     "기존 프로젝트 수정"을 고르면 output_path는 실제 존재하는 폴더여야 하고(없으면 에러),
     업로드한 파일은 전체 요구사항이 아니라 "변경 요청"으로 처리되며, 에이전트가 기존 구조를 먼저
     파악한 뒤 최소 범위로만 수정합니다. **언어/프레임워크 등은 입력하지 않아도 됩니다** — 비워두면
     에이전트가 프로젝트 폴더를 직접 읽어서 자동으로 판단합니다(경로만 정확히 입력). Git으로
     버전관리 중인 프로젝트를 권장합니다.
   - **참고할 기존 코드/프로젝트가 있다면** "참고 코드 레퍼런스"에 로컬 경로를 추가하세요 (브라우저
     업로드가 아니라 경로 입력 — 로컬 프로그램이라 Claude Code가 직접 읽습니다). 설계·개발 에이전트가
     스타일 · 패턴만 참고하고 그 경로 자체는 수정하지 않습니다.
   - 프리셋(전체납품/표준/프로토타입) 또는 커스텀으로 실행할 에이전트를 고릅니다.
     커스텀을 고르면 일단 전체가 켜지고, 필요 없는 것만 체크 해제하면 됩니다. 의존성이 깨지면 경고가 뜹니다.
   - **"선택한 에이전트로 파이프라인 시작"** 버튼을 누르면 대시보드가 엔진 프로세스를 직접 실행합니다
     (터미널을 따로 열 필요 없음). 데모(드라이런) 모드 체크박스로 Claude Code 없이 흐름만 먼저 확인할 수 있습니다.
2. **"② 진행 현황" 탭**에서 실시간 진행 상황을 봅니다. 요구사항 확정 / 설계 확정 / 최종 납품 3곳에서는
   **해당 단계 에이전트가 만든 산출물 요약이 먼저 표시**되고, 그 내용을 확인한 뒤 "승인하기" 버튼을 누르면
   다음 단계로 넘어갑니다 (즉, 승인 버튼은 "이 산출물 보고 다음 단계로 진행해도 좋다"는 의미입니다).
   내용이 길어서 화면에서 보기 불편하면 **"⬇ HTML로 다운로드"** 버튼으로 독립된 HTML 파일로 받아서
   따로 열어보거나 다른 사람과 공유할 수 있습니다.
3. 진행 중 이슈가 생기면:
   - 대부분은 에이전트끼리 자동 해결 (Tier 1/2) → **"이슈 히스토리" 탭**에 자동으로 기록만 됩니다.
   - 정말 중요한 것만 (Tier 3) → 같은 탭에서 "사람 결정 대기"로 표시되고, 결정을 입력하면 재개됩니다.
4. **"CTO 대화" 탭**에서 사람은 이 창구 하나로만 "지금 어디까지 됐어?", "결정 필요한 거 있어?" 같은
   질문을 하면 됩니다. PM이나 다른 에이전트에게 직접 물어볼 필요가 없습니다.
5. 프로젝트가 끝나면 **"지식 베이스" 탭**에 재사용 가능한 기술 패턴이 쌓여, 다음 프로젝트의
   설계/개발 에이전트가 같은 실수를 반복하지 않게 됩니다.

### 엔진을 터미널에서 직접 실행하고 싶다면 (선택사항)
대시보드의 "시작" 버튼 대신 아래처럼 직접 실행해도 동일하게 동작합니다.
```bash
npm run engine        # 실제 모드
npm run engine:demo   # 드라이런 모드
```

### 상태 초기화 (새 프로젝트 시작)
```bash
# state 폴더의 진행 상태만 초기화 (지식 베이스는 유지하고 싶다면 knowledge/ 폴더는 남겨두세요)
rm state/pipeline_status.json state/approvals.json state/issues/issue_history.json
rm -rf state/agents/*.json state/uploads/* state/engine.log state/engine.pid.json
```

## 5. 아직 확인/검증이 필요한 부분 (그대로 인지하고 시작하세요)

이 프로젝트는 대화를 통해 설계된 요구사항을 최대한 반영한 **동작하는 스켈레톤**입니다. 다만 아래는
실제 로컬 환경에서 직접 확인 후 코드를 조정해야 하는 부분으로, 코드 곳곳에 `⚠️ TO VERIFY` 주석으로
표시해뒀습니다.

- `engine/lib/claudeClient.js` — ✅ `--permission-mode acceptEdits` + 15분 타임아웃 이미 추가함
  (7번 섹션 "크리티컬" 참고). **남은 확인 사항**: 이 모드가 Bash 도구까지 커버하는지, 안 되면
  `--allowedTools "Bash,Read,Edit,Write"`를 추가해야 하는지 로컬에서 실제로 확인 필요.
  또한 `--print`/`--output-format`/`--model` 등 기본 옵션명 자체도 `claude --help`로 재확인하세요.
- `engine/lib/usageMonitor.js` (대시보드는 `dashboard/lib/engineBridge.ts`를 통해 이 파일을 그대로
  재사용) — `~/.claude/projects/**/*.jsonl` 세션 로그의 `message.usage.input_tokens` 등 필드 경로가
  실제 로컬 파일과 일치하는지 확인하세요.
  (참고: `/usage` 명령은 헤드리스 모드에서 작동하지 않는다는 것을 Anthropic 공식 문서로 확인했습니다 —
  그래서 로그 파일을 직접 파싱하는 방식을 씁니다.)
- `engine/config/pipeline.config.json`의 `models` 섹션 — 역할별로 다른 모델(Opus/Sonnet/Haiku 등)을
  쓰고 싶으면 여기에 지정하세요 (예: `"design": "claude-opus-4-8"`). 비워두면 Claude Code 기본값 사용.
  **단, 실제 `--model` 플래그가 받는 모델 이름 문자열은 `claude --help`로 확인 후 넣어야 합니다.**
- `dashboard/app/api/cto/route.ts` — 이제 실제로 로컬 `claude` CLI를 호출해 자연어로 답합니다
  (평소엔 상태 요약 카드만, "더 자세히"라고 요청하면 해당 에이전트 원본 히스토리 최근 6턴을 함께 참고).
  CLI가 설치되어 있지 않으면 자동으로 규칙 기반 요약으로 폴백합니다.
- `engine/agents/dev.js` — 지금은 "코드를 작성하라"는 지시만 내리는 자리입니다. 실제 파일 편집까지
  하려면 Claude Code의 파일 편집 도구 호출과 연결해야 합니다.
- `engine/lib/authCheck.js` — `claude auth status --text`가 실제 설치본에서 그대로 동작하는지 확인하세요.
  버전에 따라 명령 형태가 다를 수 있습니다.
- **참고 코드 레퍼런스 경로 접근 권한** — cwd(output_path)와 다른 위치의 레퍼런스 경로를 Claude Code가
  실제로 읽을 수 있는지 확인이 필요합니다. 안 되면 레퍼런스 경로도 허용 디렉토리로 추가하는 CLI 옵션을
  찾아 `claudeClient.js`에 반영해야 합니다.

## 6. 알려진 구조적 한계와 해결 현황

이전 시니어 리뷰에서 발견된 3가지는 다음과 같이 처리했습니다.

1. **엔진/대시보드 간 코드 중복 → 해결됨.** `dashboard/lib/engineBridge.ts`가 `engine/lib/claudeClient.js`,
   `usageMonitor.js`, `authCheck.js`를 경로로 직접 `require()`해서 재사용합니다. 대시보드 전용
   복제 파일(`claudeCli.ts`, `usageCheck.ts`, 중복 인증 함수들)은 전부 삭제했습니다. 이제 로직은
   한 곳(engine/lib)에만 존재하고, 대시보드는 그걸 가져다 쓰기만 합니다.
2. **단순 단계는 실패 시 수동 재실행 필요 → 해결됨.** 기획/설계/PL/보안/문서화/배포/납품도 개발·리뷰·
   테스트와 동일하게 `runWithPmRouting`으로 통합해서, 이제 12단계 전부 PM의 Tier 분류(자동재시도/
   가정후진행/사람에스컬레이션)를 거칩니다.
3. **클라이언트단 입력 검증 부재 → 해결됨.** "기존 프로젝트 수정"인데 경로가 비어있거나, output_path
   자체가 비어있으면 대시보드에서 API 호출 전에 바로 막고 안내 메시지를 띄웁니다.

이 외의 설계 배경(왜 이런 선택을 했는지)은 `docs/requirements.html`의 "06. 결정사항 & 확인필요" 탭에
그대로 남아있습니다.

## 7. 최종 사인오프 전 체크리스트 (시니어 리뷰 결과 2차)

**🔴 크리티컬 — 이미 수정됨**: 헤드리스 모드에서 도구(파일읽기/쓰기) 사용 시 권한 프롬프트에 막혀
영원히 멈추는 문제. `claudeClient.js`에 `--permission-mode acceptEdits`와 15분 타임아웃 안전장치를
추가했습니다. **다만 Bash 도구까지 이 모드로 커버되는지는 로컬에서 실제로 한 번 돌려보고 확인이
필요합니다.**
